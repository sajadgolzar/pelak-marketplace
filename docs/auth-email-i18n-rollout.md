# Multilingual Auth Email Hook — NOT LIVE

This PR stages a Supabase Send Email Hook using Resend. **Do not deploy/enable it yet**: activating a hook replaces *all* Supabase auth email delivery, including password recovery and email changes. This implementation intentionally rejects unsupported actions, so enabling it prematurely would break existing login/recovery flows.

## Design
- Supported languages: Persian (fa), English (en), Arabic (ar), Georgian (ka). Fallback: en.
- OTP is supplied by Supabase's signed Auth Hook payload, not generated by the client.
- The locale is read from `user.user_metadata.pelak_locale` or `locale` (not trusted for authorization).
- **Important limitation:** user metadata may be absent/stale on first login. For language-per-request, implement and verify a safe way to persist the selected locale before triggering OTP, without permitting unauthorized changes to another account.
- The sender must be an approved, verified Resend sender. No keys are stored in Git.

## Before activation
1. Back up current Auth templates and verify recovery, signup, change-email and invitation flows.
2. Add full templates for all Supabase Auth email action types and test them, including recovery and change-email. Do not activate this partial implementation.
3. Configure `RESEND_API_KEY`, `SEND_EMAIL_HOOK_SECRET`, `PELAK_AUTH_EMAIL_FROM` as protected function secrets. Ensure the Auth Hook secret and endpoint verification are correct.
4. Confirm Supabase Hook authentication behavior and signature validation with a signed staging payload.
5. Add locale selection to native and web OTP requests and verify existing users/new users in all four languages.
6. Test 6-digit code verification on Android and web, resend throttling, failure behavior, and password recovery.
7. Only then enable the hook, deploy a staged release, monitor and have a rollback path to the previous templates.

This change does not touch the public site, APK, Auth configuration, or database.
